# 天意人力资源系统操作手册 V12

2026年11月18日更新。当前运行242版。先阅读末尾新版薪酬章节；工资项目公式、直接工资表及Excel入口以新版章节为准。其余完整功能章节保留；旧功能截图保留原取图版本说明。

本手册覆盖门店员工、店长、HR、薪酬、老板、供应商与配置人员的日常操作。先确定人员、真实工作关系与组织范围，再办理排班核勤、各业务核定和工资汇总。页面截图标明实际来源版本，操作与结果以当前授权和业务状态为准。

本资料不含口令。完整77账号及初始口令仅放本地账号手册。

## 1 登录与工作范围

入口：我的工作台。适用角色：所有操作人员。

先使用管理员分配的账号登录。系统按角色显示入口，页面顶部的集团、品牌公司和门店决定当前浏览范围。门店人员从本人门户办理日常事项。

1）登录后确认右上角身份，再确认顶部集团与公司范围。切换范围后，等待页面完成刷新。
2）首页按当前角色显示最多六个常用入口。完整菜单仍列出全部已授权功能，店员、店长与系统配置人员的工作焦点分别显示。
3）在左侧展开业务分组，通过二级菜单进入页面。手机点左上角菜单；底部提供工作台、人员、薪酬或搜索等获授权快捷入口。
4）点击查找功能与页面，输入花名册、月报、工资等关键词。搜索结果只列当前账号可进入的页面。
5）列表搜索用于收窄当前业务记录。每页条数和上一页、下一页用于翻页；改变搜索条件后从第一页重新查询。
6）单击详情、员工姓名或员工全貌，可以查看来源记录。敏感字段和原件下载仍按当前权限重新核验。

办理结果：同一账号可见的菜单、公司、人员及字段分别受控。功能账号与员工自助账号可以关联同一永久人员。

使用说明：账号及初始口令见本地账号手册。本资料不包含口令。demo用于全部功能演示，admin用于系统配置；正式使用应设置独立账号。

## 2 集团品牌公司与门店基础

入口：人事管理 / 人事组织架构。适用角色：集团HR总监、组织配置人员；新建独立集团由获授权的配置管理员办理。

帐套可以覆盖集团，集团下建立品牌公司，再管理各门店。门店作为独立公司记录，不用部门代替核算主体。集团、品牌公司及门店都可以设置部门和岗位。

1）首次空库由初始化账号创建集团、帐套与总部；已有组织中的新建集团帐仅由获授权的配置管理员办理。集团内品牌使用创建品牌公司，建立正确上下级关联。
2）点击新增组织 / 岗位，先选所属公司，再维护部门、岗位与档口。档口关联部门或工作区域，岗位保持通用岗位定义。
3）维护组织启停状态及上下级关系。人员任职和编制按各自有效期间接续；组织基础登记不提供一套通用有效日期编辑。
4）组织设置按当前版本与保存结果更新，避免并发覆盖。核定编制等有独立发布状态的记录须另行由不同自然人核准，不能把所有组织保存都称为待审批。

办理结果：天意集团下包含香香鱼米和大富烤肉，各有10家门店。大富烤肉门店使用香港地区与港币场景。

使用说明：组织上下级、法律雇主、发薪主体及成本承担分别记录。配置管理员可设置组织，不因此取得关联人员、原合同或工资字段。

## 3 组织架构图与编制

入口：人事管理 / 人事组织架构。适用角色：集团HR 品牌HR 店长及老板。

树状组织图用于逐级展开，网状组织图用于查看组织关联。组织节点可以进入人员明细，编制与空缺页核对部门和岗位容量。

1）切换树状组织图或网状组织图，再选择部门与档口、岗位与职级或集团岗位体系维度，查看当前授权节点。
2）打开节点详情，查看所属关系、岗位和当前人员，再进入员工全貌核对任职。
3）切换编制与空缺，按部门或岗位范围查看核定人数、FTE、在岗人数、招聘占用和剩余名额。
4）需要调整时点击核定编制，填写部门或岗位范围、版本、核定人数、FTE及有效期间，保存草稿。另一名有权人员在编制与空缺点击独立复核发布，再核准发布。
5）分别检查满编、超编和有空缺的记录，确认招聘需求采用正确公司及岗位编制。

办理结果：编制记录与人员任职、招聘占用使用同一组织基础。图中人数按当前日期及授权范围计算。

使用说明：组织图是查看入口，编制核定是有版本的业务操作。老板账号以只读查看为主。

## 4 人事花名册与员工全貌

入口：人事管理 / 人事花名册。适用角色：集团HR 品牌HR 普通HR及授权店长。

一个人保留同一集团内的永久人员编号。入职新门店、跨品牌任职及离职后再入职，新增实际雇佣经历，沿用原人员主档。

1）使用姓名、永久编号或关键词搜索花名册，在全部人员、当前在职、历史雇佣、待入职之间切换。
2）点击显示字段，选择本次需要的列。Excel导入先下载或核对当前模板，上传后检查预检结果，再提交执行。
3）点击姓名进入员工全貌，核对个人资料、各公司任职、部门岗位和入离职时间。
4）继续查看合同、考勤、假期、绩效、学习考试、证件、住宿及领用等已关联记录。业务来源各自保留状态，尚待核定的记录保持待核。
5）跨店历史统计与福利发放优先用永久编号识别，不用姓名或当前门店编号重新创造人员。
6）学习记录按考试成绩、学习任务、培训签到、带教实操、培训纪律、岗位资格和结果应用分区查看；考勤及工资可按月份核对。字段受控时不由其他分区拼接补齐。

办理结果：集团HR总监可在授权集团内查看跨品牌完整经历，品牌与门店账号查看各自授权片段。

使用说明：人员主档、操作账号、实际雇佣及岗位任职是不同记录。原登记法律雇主、当前已核法律雇主及适用起日分别显示，未核不冒作已确定主体。多段合法关系不会自动合并为一份工资。

## 5 入转调离与多店任职

入口：人事管理 / 入转调离。适用角色：集团HR 品牌HR及普通HR。

入职、转正、调动及离职从统一办理单发起。人员编码保持连续，组织和薪酬按核定日期接续。

1）选择人员后发起人事办理，明确办理类型、生效日期、原公司与目标公司。
2）新入职先核对既有人员是否已存在。跨店或再次入职选择原人员主档，录入新的实际关系及合同资料。
3）部门岗位调整填写目标部门、岗位和职级，待遇变化按相应来源另行核定。
4）提交后检查核准状态及实际生效。流程获批后仍须核对业务是否已经执行，不以阅读提醒代替实际办理。
5）完成后回到花名册及员工全貌，确认原关系结束日、新关系起点和岗位历史。
6）在入转调离切换法律雇主资料核定；有据提出补录，由独立人员核定后明确采用，保留原登记资料及核定适用起日，不因换店名称推断主体。

办理结果：入离职经历、合同待遇和工资计算可以按有效期间相互核对。演示中保留同人跨品牌、跨门店及多次入职记录。

使用说明：调班和门店借调在排班考勤办理；实际法律关系变更在人事办理，不用修改一条当前门店字段覆盖过去。

## 6 招聘需求到入职

入口：招聘管理 / 招聘管理。适用角色：招聘专员 面试官及集团HR。

招聘从编制需求开始，连接候选资料、面试、录用及入职办理。候选人转为员工后继续使用统一人员和任职记录。

1）建立招聘需求，选择公司、部门、岗位、人数与目标日期，检查编制占用。
2）切换招聘来源。已核飞书招聘读取需先配置企业授权、连接及来源；未配置时用带原件的Excel/PDF导入。不同HR人工接收后仍须完成原生简历复核、面试、Offer和显式入职。
3）录入候选资料，上传简历原件或按模板导入。打开简历复核，确认识别或整理后的字段，不以文件上传代替内容核对。
4）安排面试轮次、面试时间和评价人，面试官在获分配的任务中提交评分与结论。
5）录用前核对拟入职日、岗位和薪资条件。按相应审批办理录用，生成后续入职来源。
6）在Offer与入职按当前允许动作办理正式入职，再到人事花名册和入转调离核对实际人员、雇佣与任职结果。原简历、面试、Offer送达和候选反馈分别可追溯。

办理结果：当前演示提供需求待审、新候选、面试、录用和入职衔接等不同状态的演示记录。

使用说明：平台来源重复、更新、明确不活跃、同时间冲突及旧版迟到分别保留。招聘站或平台未配置企业授权时不声称已连通，不按同名自动合并人员。

## 7 合同待遇与到期提醒

入口：人事管理 / 人事合同及合同到期提醒。适用角色：HR 合同管理员及获授权员工。

合同保存签约公司、有效期间、原件和结构化待遇。签署材料核验、条款独立核准、明确生效、给薪映射及工资采用分别办理。

1）在人员或合同列表新建合同，选择员工实际关系、签约公司、合同性质及起止日期。
2）上传合同原件，核对工资、奖金、工时和其他待遇字段。附件保存与待遇字段确认分别办理。
3）按允许动作核验真实签署；结构条款先核准条款，再明确办理生效。计薪来源中的参考额或参数不等于已采用工资，必要时进入合同给薪核定补齐映射。
4）打开合同到期提醒，按到期日和公司筛选。提醒记录区分阅读与办理进度，续签草稿不会提前关闭原合同。
5）办理续签、变更或终止后，回到员工全貌核对原合同、新版本和有效期间。
6）有效结构条款行点击给薪核定，自动带入原合同与条款。合同签署、条款生效、映射核定和工资采用分别办理。

办理结果：HR和员工门户可查看各自授权的提醒与合同。合同待遇影响后续工资时仍须正常核算和复核。

使用说明：纸签扫描件和电子签材料分别核对。电子签完成须取得对应正文、版本、主体、日期与服务商验证材料后，由HR明确登记原生签署；条款仍须独立生效。

## 8 高级排班与手动画班

入口：排班考勤 / 排班工作台。适用角色：店长 考勤专员及集团HR。

原始基线只读，编辑从新建排班草稿开始。日时间轴、周班表、月日历提供不同观察范围，一天允许安排多段班次。

1）选择2026年10月及工作日，确认公司范围和排班版本。点击新建排班版本，由已有版本复制或建立新草稿。
2）切换日时间轴，在手动画班模式拖出班段；调整画线吸附分钟，或点精确输入填写开始、结束和休息段。
3）在选择与移动模式选择班段并拖动。按Ctrl拖动用于复制（Mac也支持Option）；提交前核对本次复制或移动的目标人员、日期与时间。
4）选择多个班段后点击复制到其他日期，核对跨夜时间、一天多班次、休息安排及重叠提示。
5）在班次设置新增班次、休息段和颜色。颜色图例用于区分早班、晚班、收尾或其他班型。
6）草稿完成后交另一位有权人员复核发布。手机以人员班段卡片查看，复杂画线操作使用PC。

办理结果：发布的新排班以实际人员、日期和有效正常班段支撑请假核量及核勤来源；不计薪休息先扣除，加班计划不进入普通假期分钟。原始基线和排班修订版本分别保留。

使用说明：排班是计划。实际工时需要打卡或有据核定。相关班段、休息或完整工作日分母变化后，尚未实际已休的旧申请须重新核量，不能直接覆盖数量；已休及已确认工资保留当时来源。

## 9 打卡调班与门店借调

入口：我的办理 / 我的排班与考勤及排班考勤 / 调班与借调。适用角色：门店员工 店长及考勤专员。

本人打卡、员工换班、个人调班和门店借调保留不同来源。调班审批与最终应用分开，接收门店服务记录不会重复造一份雇主工资。

1）员工在我的排班与考勤查看自己的班段，点击本人打卡，核对实际关系、班段与方向后提交。
2）通过调班或借调申请填写原班段、目标安排、借调门店及原因。需要对方确认时等待原对方处理。
3）店长或HR在调班与借调查看内容与差异，按当前审批状态办理。
4）获批后检查实际应用状态，核对是否生成排班草稿、是否已按规则发布，以及人员所属和实际工作门店是否正确。
5）迟传和补充的原卡通过来源接入核查或有据更正处理，原始发生时间保留。
6）从原调班、借调或补卡单提交当前公司已绑定的已发布审批流，不另造第二笔来源。需要对方确认时先由对方本人确认。
7）审批获批后由有权人员实际办理。调班先形成新的排班草稿，再独立复核发布；来源变版或已取消时阻断旧单继续执行。

办理结果：演示包含待对方确认、待审、驳回、获批待应用和已更正等记录。

使用说明：钉钉、飞书、企微或设备来源需要另行配置对照。当前本地打卡与外部原卡分开留痕。

## 10 HR考勤日报月报与版本

入口：排班考勤 / 考勤日报及考勤月报。适用角色：考勤专员 店长及薪酬专员。

HR核勤同时查看计划、实际打卡和核定结果。缺失证据保留未知值，核勤更正生成另一版本，原确认版本仍可查看。

1）选择月份、工作日和核勤版本，按姓名、永久编号或公司筛选。日报查看每人每天，月报查看员工月份汇总。
2）打开原值与明细，在核勤值查看计划工时、实际打卡、核定在岗、加班、迟到早退和缺卡；未知原始值与已核数值分别显示。
3）切到请假来源，核对实际已休记录、待遇分类已核或待核、净分钟及原核勤已含时长（已计入部分不重复增加）。月度来源分页查看，按分段待遇逐段核对；点击当前请假原单时重新检查权限，不展示医学原件或给薪金额。
4）需要人工更正时新建核勤草稿，点核定调整，录入实际值、原因和证据引用；不要把未知值随意填零。
5）请假或待遇依据变化时，原报表会提示需重新核定。新建核勤版本，明确选择复制当前已核报告；若保留原核定值，勾选重新核对请假来源的人工复核选项并填写原因与依据。新版本保留原值及来源，待核待遇仍待核。
6）由另一名有权限人员复核确认本版本。工资的新预演与采用重新检查该员工月份核勤的当前来源；原已确认工资和旧核勤历史不回写。
7）导入Excel先预检。日报导入与月汇总导入分别选择；月汇总不生成并不存在的逐日打卡。
8）使用导出Excel交付HR核对表，在版本记录中追溯新旧报告。

办理结果：原值、调整值和当前有效版本能够相互核对。内地与香港工资使用各自适用的已核数据。

使用说明：审批通过不等于实际已休；部分给薪比例不拆成另一段无薪假分钟。核勤分类、假期待遇和工资金额分别核定。跨店雇主汇总与接收门店视图不相加；人工复核版本不自动认可待核待遇或重新发薪。

## 11 高级假期与人工核定

入口：排班考勤 / 假期台账及假期设置。适用角色：假期管理员 HR及员工本人。

政策版本、实际关系、额度批次、申请占用和实际已休分别记录。规则提供人工核定入口，用于补充地区、人员资格或原始证据尚不确定的情形。

1）在假期设置查看地区、政策性质、单位和有效期。新建或修订政策后，由另一位有权限人员复核发布。
2）在假期台账核实人员实际关系，再按政策发放额度或维护有据期初。打开账户查看可用、占用和已休。

4）批准后先保留占用，HR按实际发生确认已休。相关排班在批准或实际已休前发生变化时，旧申请保留但不能继续按旧数量执行；取消会释放原占用，重提使用新尝试编号和当前排班依据，不回写旧申请。
5）额度需要调整时先保存预演意图，由另一人检查基线后生效。法定负向更正和到期处理保留专门依据。

8）如哺乳等无余额周期带薪工作时段，先核定资格、期限、时窗及每日上限，由不同自然人核准。候选只来自正式净工作时段，纯休息、无薪间歇及仅加班不生成候选。取消重提沿同一发生和权益根承接，时长增加只追加有据正差，减少不回收旧授予；新申请仍受实际净分钟和跨窗每日上限约束，批准后另核实际发生。

使用说明：模板待核不等于规则已经发布。当前假期直接申请使用证明引用；原件上传应通过已接入的资料或申请表入口，不宣称此表已自动上传附件。

## 14 中国内地与香港薪税核验

使用说明：行业日额表、原工资期分组、逐日收入和人员资格分别核对。部门及字段权限适用于列表、搜索、核定和当前版本；资格或来源撤销后不能继续核准。界面及隔离协议验收不代表真实供款或机构受理，适用政策仍须核验地区、日期及客户事实。

4）核准物品单后，由有权限人员确认实际交接，库存才按采购入库、领用出库或关联退回发生变化。取消未办理单和更正单保留原依据。
5）按人员、用途和时间查看统计，在员工全貌查看本人领用及福利发放经历。

办理结果：系统将简单库存数量、申请、审批和个人领用记录衔接起来。

使用说明：本模块为人事行政轻量流程。用途、个人领用及按单位/币种分列的统计关联人员，辅助金额不代表采购付款或已采用工资，采购源成本与领用归属不重复相加。

## 23 服务量对账与外包结算

入口：用工与服务 / 服务量与对账及供应商资金。适用角色：外包人事专员 财务复核及供应商。

服务量先核定，按已核合同价目形成对账，再经供应商确认、应付、付款和银行事实处理。员工工资代发另外核对逐人授权与到账结果。

1）核定服务总量时选择当前雇主考勤来源，明确截止日期。正常分钟与加班分钟合计一次，工作地分摊不再增加原服务总量。
2）维护合同价目、阶梯单价、币种和价税口径，独立核准后建立月度对账。打开对账明细核对服务来源和金额。
3）内部复核后共享给供应商，供应商确认或提出异议。有权人员确认形成应付，修订按累计目标差额登记。
4）核定历史资金期初，按可用应付申请付款，复核后生成工作底稿。登记银行实际结果，未知继续占款。
5）预付、发票关联和退款分别处理。缺发票不阻断员工无争议工资；退款不通过负付款模拟。
6）工资代发核对先核准个人授权和净工资指令，确认资金占用，再核对成功、失败、未知及退款等逐人结果。
7）工资代发核对单独查看个人授权、净工资指令及逐人结果，不以一笔供应商汇款认定所有员工收到工资。用工沟通中HR内部备注不向服务人员或供应商自动公开。

办理结果：演示含共享、争议、应付、付款未知、工资代发核对和逐人沟通。具体账单、归属月及状态以最终场景索引为准，供应商收款不代替员工到账。

使用说明：生成付款底稿不表示已发银行；服务费、员工代发资金和人力成本有独立归属，防止重复计成本。

## 29 HR月结操作顺序

入口：跨模块月度工作。适用角色：集团HR 考勤薪酬及财务复核。

月结先确认人员、组织和实际发生，再核定请假来源、核勤与各项待遇，最后汇总工资、支付与成本。每一步保留可复查来源。

1）核对本月人员入转调离、实际雇主、合同待遇及参保纳税资格，确认期间和人员编码连续。
2）发布最终排班，处理调班借调和原卡；计划与实际出勤分别保留，未知工时不强行补零。
3）按实际发生核定已休，明确假期待遇分类及给薪事实；仅获批准但未实际已休的申请不作为已休扣勤。
4）在当前来源上核定考勤日报及月报。来源变化时新建有据复核版本，必要时明确保留原核定值并由另一人确认，不回写旧报告或原工资。
5）完成绩效正式奖金、培训奖励、住宿费用等核准，明确哪些进入工资和哪个发放月。
6）按公司和体系预演工资，核对当前考勤、假期给薪及合同等来源，独立复核后采用和确认，发布个人工资单。
7）核对收款资料、资金期初、付款占用与机构结果；工资、外包及员工代发渠道共同核对余额。
8）查看人力成本和待核清单，导出核对资料，备份系统并保留版本。

办理结果：月结交付包括考勤日报月报、工资项目与工资单、付款申报核对、外包对账及成本来源。

使用说明：重新打开已确认期间必须有明确更正来源和权限。更正保留旧版与本次净差，不覆盖原历史。

使用说明：登录入口、账号对照或通知引用不增加业务权限；以当前完整授权和已核配置为准。

## 32 审批结果通知与原单穿透

## 33 合同电子签与材料核定

入口：集成设置 / 合同电子签；人事管理 / 人事合同。适用角色：集成管理员 HR及独立复核人。

电子签外发意图固定正文、版本、主体、PDF原件与签章位置。平台流程完成、材料验证和本地签署登记分步处理。

1）先核准连接、个人及机构经办人映射。
2）在具体合同创建外发意图，核对原件与签署位置，另一人员独立核准。
3）开启真实外部任务须专门部署开关及明确操作。结果未知时不重复创建或开启，已知流程只安全回读。
4）取回对应材料和服务商验证报告后，HR独立核定并显式办理原生合同签署登记；改稿必须重新收集材料。

办理结果：标准演示仅保留配置、待复核和等待后台办理，无外部流程或伪造签署回执。

使用说明：演示不发起真实签署，不代表任何客户企业已接入服务商。纸签仍走独立材料核验路线。

## 34 法定假期待遇与工资差减

入口：排班考勤 / 假期台账 / 给薪核定。适用角色：假期HR 薪酬专员 独立复核人。

假期数量和工资待遇分别核定。待遇政策、实际已休、资格、给薪基数、已覆盖正常工资共同决定新增给薪或差减。

1）建立适用地区、待遇类型和有效期的政策，由另一人员独立核准。
2）从原请假单核定实际已休日期、数量、人员资格、待遇基数及已含在月薪中的覆盖金额。分钟来源和日分母沿申请时冻结的净排班核对；跨午夜按民用日分片，同时保留各原排班日分母，不从后来班表重新猜算。
3）另一名独立且非受益人员核定给薪事实。未知基数或病假资格等必要证据继续待核。
4）工资计算选用已核待遇，区分新增给薪与正常工资应发差减，预演、复核并采用。
5）更正沿原义务净差处理；香港工资、强积金与最低工资所需核验分别办理。

办理结果：香港4日病假已独立核定并形成更正工资：原正常工资已覆盖2806.44港元，核定待遇2560.00港元，本次新增给薪0.00港元、应发差减246.44港元；雇员及雇主强积金各净差负12.32港元。原已确认工资保留。

使用说明：获准休假不等于金额已入工资。已休记录保留当时依据，更正沿新事实和净差办理；跨午夜的精确日份额不可用固定8小时或粗略日上限替代。正常工资已覆盖部分不能重复发放。

## 35 合同给薪映射与工资采用

入口：薪酬管理 / 合同给薪核定。适用角色：HR 薪酬配置人员 独立复核人。

原合同结构条款先核定项目、期间、单位和折算，再进入同一工资公式或独立现金义务。

1）从原有效合同条款行给薪核定直接进入，选择同公司本期已核工资方案。
2）基本工资选择明确公式输入与单位，填待遇半开归属区间及整数分子分母；整月1比1也要明填。
3）保存草稿后由另一自然人且非受益人独立复核。核准不产生工资。
4）建立相同公司、体系、方案和工资采用月的工资批次，选择同一实际雇佣的工资档案和合同参数。一次性或按期现金义务须先在工资方案核准合同来源待遇，再明确选择，不能同项双发。
5）逐项核对目标、原已确认及本次净差，再独立复核、采用和确认工资；返回核定列表查看实际采用状态。

办理结果：标准演示保留内地与香港两条已核参数及一条待独立复核参数，未生成11月工资。工资档案、核勤和薪税资格齐备后再正常预演，是否形成工资按实际采用状态判断。

使用说明：未知映射不默认零；基本工资不能再作为第二笔现金。月中片段须覆盖完整实际在职区间，原合同和已确认工资不回写。

待审批、抄送与申请人结果通知按具体业务用途配置。规则核准人明确授权本账号后台投递，接收者仍须有当前原单阅读权。

2）另一位有当前业务权限的HR点击独立核准并授权本账号后台投递。配置admin不因建规则获得业务阅读权。

## 37 空库初始化与首个集团

入口：首次配置 / 创建首个集团。适用角色：首次初始化管理员 系统配置人员。

4）按真实需要配置部门、岗位和操作人员，功能、字段与数据权限分别核定。

## 38 到期提醒与通知

入口：集成设置 / 到期提醒与通知；我的办理 / 提醒通知。适用角色：有原业务及集成授权的HR、业务经办及获通知员工。

合同到期、证照到期、入住期限和房源租约到期分别读取原业务日期。规则配置、站内提醒、通知投递、平台回执与租约日期分区管理。配置人员在连接设置维护前置资料，业务HR核对来源并明确授权后台投递。

1）在规则配置点击新建到期规则，明确企业连接、已核内部应用、四类提醒事项、时间窗口、时区、收件账号和允许的固定访问源地址。内部应用可留空保存待配置草稿；另一名有当前原业务权限的HR独立核准并授权本账号用于此规则后台投递。
2）使用生成站内提醒核对当前有权事项，查看新增站内条数与外部任务0条；后台投递另行记录。每日提醒或阈值日可选，正数为到期前、负数为到期后，均限定在已设窗口内。
3）在租约日期点击记录租约日期，选择房源，填写日期来源编号、起止日与凭据；租约截止日含当天。另一人明确核定通过或驳回。停止日期来源只停止后续日期提醒，不终止租约或办理退宿。
4）在通知投递分别查看队列、平台受理、送达依据及阅读状态。核对后恢复投递须重新满足当前权限、映射和来源；已受理或结果未知不能靠重建任务重复发送。
5）对支持的平台在通知投递点击查询平台回执，只建立真实查询任务；结果在平台回执中查看。企业微信通用文本没有已核的通用阅读回读能力，不生成假已读。
6）员工从提醒通知或确切平台链接打开提醒概况与原业务当前资料。重新核对会按当前权限重取，健康证编号按授权遮盖，不显示工资或私密正文。续签、已核替代、离职、换房退宿或租约日期变更后，旧周期停止，历史仍按当前权限查看。

办理结果：规则、站内提醒、平台受理及阅读分别留痕；租约日期保留独立核定版本。标准演示仅展示合法待配置、已核日期及站内状态，没有真实外发或伪造平台回执。

使用说明：业务到期提醒不创建审批实例，不提供审批动作。点击提醒和标记已读不代表续约、换证或退宿完成。


## 一、从工资项目进入公式

在“薪酬管理 → 工资项目设置”找到项目，点击该行“设置公式”。选择公司或门店的工资方案，可看到该项目在方案中的现行公式；选择“设置公式”建立新修订。不同门店可以为同一项目使用不同公式及有效期间。尚待复核的自定义项目须先由另一位有权人员发布，再加入工资方案。

编辑窗口的“规则与参数”提供：输入变量、项目与公式、来源待遇、跨模块取数公式。“主体与有效期”填写公司、体系、生效时间和调整依据。保存形成待复核版本，须另一位有权人员复核发布。已确认工资保持原版。

## 二、普通公式、变量和项目引用

输入变量可以来自个人工资档案或已核考勤报告。金额、时薪、分钟、小时、天数、比例等单位分别声明，不能把分钟直接当金额。工资项目可引用本方案输入变量及其他工资项目编码；系统检查未知变量、依赖循环、单位不符和除零。

示例：

```text
monthly
round(monthly * 0.1, 2)
prorata(monthly, present_days, work_days)
if(monthly >= 10000, 500, 200)
max0(monthly - 5000)
round(BASIC_MONTHLY * 0.05, 2)
```

示例中的变量必须先登记并提供已核值；不是内置字段的名称不会自动变成业务数据。正式算薪缺失来源时阻断，不能把未知当0。

“函数库与可引用数据”可查看函数签名、说明和示例，点击变量、项目或函数插入当前公式。“公式校验与试算”使用与服务端相同的计算引擎，输入样例数值后逐项显示结果及依赖。样例试算不生成工资；正式算薪重新读取已核数据。

## 三、函数库

| 函数 | 用途 |
|---|---|
| if | 条件取值 |
| round | 四舍五入，明确小数位；省略时沿用新版默认2位 |
| ceil / floor | 向上、向下取整 |
| abs | 绝对值 |
| sqrt | 精确有理数平方根；非精确结果会阻断，须先明确核定精度 |
| power | 整数幂，指数-16至16 |
| mod | 余数，符号随被除数 |
| min / max | 多值取小、取大 |
| greatest / least | 多值最大、最小 |
| coalesce | 首个明确非空值；不吞掉未核来源或缺失变量 |
| max0 / min0 | 以0封底、封顶 |
| prorata | 金额×实际÷应出，应出不能为0 |
| and / or / not | 布尔逻辑；也支持AND、OR、NOT写法 |

支持加减乘除、括号、比较和项目之间引用。保留“公式代码与触发器”的独立版本、代码预演与审批入口；表达式、代码扩展与实际工资确认各有状态。

## 四、跨模块数据自动影响工资

在“跨模块取数公式”增加规则，依次选择来源模块、来源项目、目标工资项目并填写公式。`source_amount`代表该人员该来源当前已核金额，可同时引用本工资方案的个人工资参数、考勤变量和普通工资计算结果。

示例：

```text
source_amount
round(source_amount * 1.1, 2)
round(source_amount + monthly * 0.1, 2)
round(source_amount * 0.5, 2)
```

- 绩效：读取当前已核准、成绩已发布且无阻断申诉的正式奖金，不会把A/B两套试算都发放。
- 培训考试：读取已核准并正式应用的奖励或技能津贴，沿用考试、资格、申诉和有效期守卫。
- 宿舍：自动读取本月已发布、同一实际雇佣、有工资扣结授权的员工费用，保留费用原始金额和结算渠道核对。
- 历史绩效：沿用既有旧新同根对照，避免同一奖金重复入薪。
- 合同、假期：通过原业务核定采用，不能借公式覆盖已核给薪；需改变金额时先办理原业务变更。

“自动取数”适用于绩效正式奖金、培训奖励、历史绩效及完整当月宿舍费用。“无来源阻断”开启时，该员工缺少所需来源或无权读取就不能继续；关闭表示没有符合条件来源时不生成该项目。此设置须随方案独立复核。

目标项目不能同时由普通公式再生成；来源的应发、扣款、福利、成本性质不能互换。宿舍费用不得超过已核授权金额。系统统一保留原来源、公式版本、输入、原金额和计算结果；来源变更后重新预演。同一奖励/费用沿原父义务确认净差，重复计算不产生第二份支付。

本轮支持统一引用已核金额及已登记的工资/考勤变量，不提供任意跨表SQL、任意未核成绩或外部接口值直接发薪。原始成绩、资格等先在绩效、培训考试模块核定并形成奖金/津贴来源。

## 五、工资表与Excel

“员工工资档案”与“批量定薪与调薪”按员工分行、工资项目分列。直接修改格子中的金额，金色标记改动并显示原值。支持Tab、Enter切换、Excel矩形金额粘贴、统一填值、按金额或比例调整。

点击上方“Excel导入”，无需预先勾选员工。下载空白CSV模板（可用Excel编辑），或上传XLSX/CSV，也可粘贴含表头的表格。按永久人员编号或雇佣编号匹配；同人多门店任职请使用雇佣编号。核对原值、新值后填入工资表，再点“保存并提交”，由另一位HR审核。空白不调整，0表示明确清零。文件含公式、外链、错误单元格、未知人员或受限项目时不能直接覆盖。

同一工资方案的新公式修订可以继续使用原有已核工资参数；新增必需参数仍须补齐。独立的另一方案不能借用已绑定其他方案的工资档案。

## 六、实测路线

1. 普通工资参数及夜班津贴公式：修改、试算、保存待审。
2. 宿舍已核费用100元，公式按50%扣结：确认扣50元，净工资4950元。
3. 同一宿舍义务改为75%：只追加25元差额，原工资保留。
4. 已核绩效1560元，公式加个人月薪1000元的10%：奖金1660元，总工资2660元。
5. 培训考试已核奖励100元，同公式加100元：奖励200元，总工资1200元。
6. 同一来源重复预演，净差为0，避免重复发放。

以上为隔离验收算例，不是客户真实工资或生产政策。两地法定政策、银行付款、工资确认和外部申报分别留状态。
